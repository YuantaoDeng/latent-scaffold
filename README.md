# Latent Scaffold

**Early Learning Shapes Later Directions of Representation Change in Continual Learning**

Experiment code for studying how early training shapes shared directions of
later representation change. The experiments cover recurrence across training
histories, paired early-content interventions, local responses, optimizer
updates, and scaffold suppression in continual learning.

## Installation

Use Python 3.12 or newer. Training requires a GPU with a compatible PyTorch
installation; several workers explicitly use CUDA.

```bash
python -m venv .venv
# Activate the environment for your shell, then:
python -m pip install -r requirements.txt
```

The requirements record the packaging environment. Select a CUDA-compatible
PyTorch/torchvision build for your machine; see [training details](docs/TRAINING.md).

## Quick start

Inspect the available scripts and print a baseline command sequence:

```bash
python run.py --list
python baseline_commands.py --model resnet18 --dataset cifar10
```

The second command prints commands without starting training. To prepare the
data before running those commands:

```bash
python prepare_data.py --dataset cifar10
python prepare_data.py --dataset cifar100
```

Dataset and pretrained-model downloads require internet access. Baseline
commands write trajectories under `results/retrained/`.

## Experiments

| Experiment | Main entry point |
| --- | --- |
| Baseline continual-learning trajectories | `sequence_drift_experiment` |
| Temporal geometry and responses | `resnet_temporal_dimension` |
| Current DeiT/CIFAR-10 rank | `recompute_deit_cifar10_current_rank` |
| MobileNet and Mixer conditions | `additional_rank_models`, `mlp_rnn_extension` |
| Paired early content | `all_model_content_worker`, `resnet_cifar100_content` |
| Optimizer updates | `run_all_multistep_updates` |
| No-replay conditions | `run_noreplay_all` |
| Fixed suppression | `all_model_causal`, `resnet_cifar10_unified_main` |
| Energy-matched suppression | Four `*_lambda100_energy_matched_queue` workers |

Run workers through `python run.py <script> [arguments]`.
[TRAINING.md](docs/TRAINING.md) lists concrete commands and prerequisites;
[EXPERIMENTS.md](docs/EXPERIMENTS.md) connects them to the saved measurements.
Follow-up workers require captured states and fitted tensor artifacts in their
expected paths. A baseline trajectory alone does not supply every prerequisite.

## Models and settings

| Encoder | CIFAR-10 rank | CIFAR-100 rank |
| --- | ---: | ---: |
| ResNet-18 | 8 | 8 |
| DeiT-Tiny | 8 | 20 |
| MobileNetV3-Small | 24 | 8 |
| MLP-Mixer-B/16 | 8 | 8 |

The paper uses AdamW, five epochs per task, batch size 64, and a replay memory
of 500 examples. Exact seeds, task orders, and intervention coefficients are in
[`configs/paper.json`](configs/paper.json).

## Data and checkpoints

Saved measurements are included for reference. Runtime outputs are created
under `results/`; that directory is not part of the distributed input tree.
Reference protocols and inventories live under `configs/experiments/`. Workers
read an existing run configuration first, falling back to the bundled reference
only for paths explicitly listed in `configs/paths.json`. Writes always target
the run directory. The multi-step worker reads `data/measurements/baseline.json`
directly. Energy-matching publication exports go to `results/publication/`.

 Dataset images, pretrained
weights, training checkpoints, and fitted tensor artifacts are supplied
separately or generated by the experiments. Historical paths and hashes inside
measurement provenance describe the original runs.

This release omits standalone plotting, frozen-result reproduction, and
verification programs. Shared numerical routines required by experiment
workers remain in `scripts/`. Full GPU training has not been rerun to validate
this package as an end-to-end reproduction workflow.
